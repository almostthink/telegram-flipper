# Telegram Gift Flipper

Настольное приложение для торговли Telegram-подарками на **MRKT**: анализ рынка
и ликвидности, поиск недооценённых лотов, покупка и продажа дороже.

Один `.exe` под Windows — при запуске поднимает локальный сервер и открывает
интерфейс в браузере.

---

## Как это работает

```
MRKT ────┐
Portals ─┼─→ Сбор листингов ─→ Справедливая цена ─→ Фильтры отбора ─→ Сигнал
GetGems ─┘   и истории сделок   (редкость модели,   (ROI, ликвидность,    ↓
                                 фона, символа,      TTS, тренд флора)  Покупка
                                 номера выпуска)                          ↓
                                                      Лестница переоценки ─→ Продажа
```

| Площадка | Роль | Состояние схемы |
|---|---|---|
| **MRKT** (`api.tgmrkt.io`) | торговля | восстановлена из записи трафика, покрыта тестами |
| **Portals** (`portal-market.com`) | цены для сверки | восстановлена из записи; подтверждено только чтение |
| GetGems | выключен | GraphQL с persisted queries — см. ниже |

Кросс-маркет сверка работает так: если лот дёшев на MRKT, но так же дёшев на
Portals, это не скидка, а новый уровень рынка. Именно эта проверка отсекает
основную часть ложных сигналов.

**Торговля только на MRKT.** У Portals подтверждены лишь запросы на чтение, а
покупать по неподтверждённому пути нельзя.

**GetGems выключен осознанно.** У площадки GraphQL с persisted queries: текст
запроса не передаётся, только sha256-хеш, который меняется при каждом
обновлении их фронтенда. Плюс коллекции адресуются TON-адресами, а не именами.
Третий источник цен не стоит такой хрупкости.

**Tonnel убран** — площадка прекратила работу.

### Справедливая цена

Две модели с плавным переходом между ними по объёму данных:

| Модель | Формула | Когда работает |
|---|---|---|
| Baseline | `флор × k_модель × k_фон × k_символ × коллекционность` | сразу, без истории |
| Регрессия | `log(цена) ~ редкость + номер + тренд`, взвешенная по свежести | от ~30 сделок в срезе |

Множители атрибутов **не перемножаются в лоб**: редкости коррелированы, и
прямое произведение переоценивает лот в разы. Полный вес получает сильнейший
атрибут, остальные — ослабленный.

Логарифм цены взят потому, что цены подарков распределены логнормально: разброс
кратный, а не аддитивный. В логарифмах зависимость линейна, а выбросы перестают
тянуть коэффициенты.

Если регрессия расходится с флором больше чем в 5 раз, её результат
принудительно зажимается в коридор — засорённая выборка не должна уводить оценку
на порядок.

### Коллекционная ценность

Рынок платит надбавку за порядковый номер и за отдельные фоны независимо от
редкости модели: подарок #1 стоит кратно дороже #40597 при одинаковых атрибутах.

Распознаются: #1 и однозначные, повторы (777, 1111), круглые (1000, 10000),
последовательности (1234), палиндромы (1221), парные (6969).

**Величину надбавки модель выучивает сама** — балл номера входит признаком в
регрессию, и коэффициент берётся из фактических сделок. Настройка в интерфейсе
задаёт только форму шкалы и работает, пока истории нет.

Коллекционные лоты дороже, но продаются дольше. Поэтому признаки влияют на
оценку цены, а не на балл сигнала: иначе система предпочитала бы то, что дольше
висит.

### Ликвидность — главный фильтр

```
score = 0.35·скорость + 0.30·время_до_продажи + 0.20·офферы + 0.15·разреженность
```

Скидка 40% на подарке, который никто не покупает, — это не прибыль, а
замороженные деньги. Поэтому ликвидность входит в итоговый балл **множителем**:
при нулевой ликвидности любой ROI даёт ноль.

Время до продажи (TTS) не берётся из API — его там нет. Оно восстанавливается
сопоставлением: подарок наблюдался в листингах, потом появился в ленте как
проданный, разница между `listed_at` и `sold_at` и есть факт.

### Экономика сделки

Комиссия MRKT подтверждена записью трафика: у каждого лота
`salePrice / salePriceWithoutFee = 1.020000`. Надбавку 2% платит покупатель,
продавец получает свою цену целиком.

```
безубыток = 2%      (MRKT, подтверждено)
безубыток = 5.3%    (площадка с комиссией 5% у продавца)
```

Отсюда сквозное соглашение: **везде хранится цена покупателя**. Она сравнима
между площадками и равна тому, что вы заплатите.

ROI считается по **консервативной** цене выхода (нижний квартиль), а не по
справедливой. Справедливая — это середина книги, а выйти нужно быстро. Иначе
прогноз систематически завышен, и на бумаге стратегия прибыльна, а на счёте нет.

### Антифрод

| Ловушка | Как отсекается |
|---|---|
| Wash trading | повторяющиеся сделки между одной парой участников; один экземпляр, перепроданный несколько раз за неделю |
| Выбросы в истории | фильтр по медианному абсолютному отклонению (MAD) внутри среза |
| Фейковый флор | одинокий лот вдвое дешевле кластера сопоставимых |
| Падающий нож | покупка блокируется при падении флора более 15% за 24ч |

Помеченные сделки исключаются и из регрессии, и из метрик ликвидности.

## Запуск

### Готовый exe

**Actions → build → артефакт `GiftFlipper-windows-x64`.** Запустите — браузер
откроется сам. CI перед выгрузкой сам запускает exe и проверяет, что он отвечает.

### Из исходников

Нужны Python 3.11+ и Node.js 20+.

```bash
cd frontend && npm install && npm run build && cd ..

python -m venv .venv
.venv/bin/pip install -r backend/requirements.txt   # Windows: .venv\Scripts\pip
cd backend && python launcher.py
```

Интерфейс откроется на `http://127.0.0.1:8731`. Если порт занят, приложение
возьмёт соседний.

### Разработка

```bash
cd backend && FLIPPER_DEV_MODE=1 python launcher.py --no-browser
cd frontend && npm run dev     # http://localhost:5173
```

### Сборка exe

```bash
python build/build_exe.py
```

PyInstaller не умеет кросс-компиляцию — **настоящий `.exe` собирается только на
Windows**. В репозитории это делает GitHub Actions на `windows-latest`.

## Первый запуск

1. **Настройки → Токены площадок.** DevTools → Network → любой запрос к
   площадке. Вставляйте значение **как есть** — приложение ничего не
   дописывает, схемы у площадок разные:

   | Площадка | Где искать | Что вставлять |
   |---|---|---|
   | MRKT | заголовок `Authorization` | собственный токен без префикса, UUID из 36 символов (выдаётся в обмен на initData через `POST /api/v1/auth`) |
   | Portals | заголовок `Authorization` | `tma <initData>` |
   | GetGems | заголовок `Cookie` | строку целиком, там `AUTH_TOKEN` и `JWT_TOKEN` — заголовка `Authorization` у площадки нет |

   Живёт 1–7 дней.
2. **Обзор → Запустить цикл.** Приложение соберёт флоры, листинги и историю.
3. **Дайте поработать сутки.** До этого момента истории сделок нет, и оценка
   опирается только на флоры атрибутов — она заведомо грубая.
4. **Журнал → Прогнать бэктест.** Посмотрите, что стратегия дала бы на
   собранных данных.
5. **Сигналы.** Покупка по кнопке. Paper-режим включён — деньги не тратятся.
6. **LIVE только после того**, как журнал наберёт статистику и покажет
   положительное ожидание на сделку.

### Если адаптер не работает

У площадок нет опубликованного API, пути меняются. Чинится без пересборки:
**Настройки → Импорт эндпоинтов из HAR**. Откройте мини-апп в
браузере, полистайте подарки, сохраните HAR (DevTools → Network → Export HAR) и
загрузите. Приложение восстановит реальные пути, расположение данных в ответе и
заголовок авторизации. Файл разбирается локально и не сохраняется.

## Безопасность

- Сервер слушает **только `127.0.0.1`** — снаружи подключиться нельзя.
- `paper_mode` включён по умолчанию.
- Автомат не включится, пока не выключен paper-режим **и** не заполнен whitelist
  коллекций. Пустой whitelist означает запрет торговли, а не разрешение всего.
- Circuit breaker выключает автомат сам: при N ошибках подряд или при
  превышении дневного убытка.
- Секреты — в Windows DPAPI через `keyring`. Если системное хранилище
  недоступно, приложение честно сообщит об этом в интерфейсе и положит их в
  файл с правами 0600.
- Данные лежат в `%APPDATA%/TelegramGiftFlipper` и не попадают в репозиторий.

## Риски — прочитайте до перехода в LIVE

1. **Официального API у площадок нет.** Это Telegram Mini Apps с внутренними
   эндпоинтами, которые могут смениться в любой момент. Схема MRKT
   восстановлена из реальной записи трафика и покрыта тестами на подлинных
   ответах; лента сделок, инвентарь, покупка и продажа в записи не встретились
   и остаются предположением. Portals и GetGems написаны по открытым описаниям
   и против живых API не проверялись. Всё чинится HAR-импортом без пересборки.
2. **Автоматизация вне ToS площадок.** Риск блокировки аккаунта, особенно при
   userbot-авторизации. Используйте отдельный аккаунт.
3. **Часть лотов заблокирована для перепродажи** — `nextResaleDate` в будущем.
   В наблюдавшейся выборке таких 5%. Приложение их отсеивает, но помните: без
   этой проверки капитал замораживается на дни.
4. **Флиппинг не хеджирует рынок.** При падении флоров инвентарь дешевеет
   быстрее, чем набегает прибыль со спредов.
5. **Бумажная прибыль — не прибыль.** Пока лот не продан и комиссия не
   удержана, рост флора ничего не значит.
6. **Бэктест — верхняя граница.** Конкуренция за лоты и очередь продавцов не
   моделируются.

Ориентир доходности при 100 TON — 1–3 TON в день после выхода на режим, при
высокой дисперсии по дням. Первый месяц закладывайте как стоимость калибровки
модели, а не как доход.

## Структура

```
backend/app/
  domain.py      общие типы: подарок, листинг, сделка, флор
  adapters/      mrkt (торговля) + portals (цены для сверки)
                 har.py — восстановление эндпоинтов из HAR
  auth/          tma-токены, userbot, хранилище секретов
  ingest/        сканер: флоры, листинги, лента сделок, восстановление TTS
  analytics/     rarity, numerology, pricing, liquidity, antifraud,
                 signals, pipeline, stats, backtest
  trading/       executor (live + paper), risk, engine
  storage/       SQLite: снимки, сделки, позиции, журнал, сигналы
  api/           REST и WebSocket
frontend/src/    React + Vite + Tailwind: 7 разделов
build/           PyInstaller
```

## Проверки

```bash
.venv/bin/ruff check backend build
.venv/bin/pytest backend/tests -q
cd frontend && npm run build
```

Тесты аналитики построены на синтетике с известным ответом: данные генерируются
по заданной формуле, и проверяется, восстанавливает ли её модель. Живой рынок
без ваших ключей недоступен, поэтому проверяется именно логика.
