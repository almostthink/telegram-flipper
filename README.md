# Telegram Gift Flipper

Настольное приложение для торговли Telegram-подарками на **MRKT** и **Portals**:
анализ рынка и ликвидности, поиск недооценённых лотов, покупка и продажа дороже.

Один `.exe` под Windows — при запуске поднимает локальный сервер и открывает
интерфейс в браузере.

> **Статус: Этап 0 из 7** — рабочий каркас приложения. Торговая логика
> подключается на следующих этапах, см. [дорожную карту](#дорожная-карта).

---

## Как это работает

```
Portals ─┐
MRKT ────┼─→ Сбор листингов ─→ Оценка справедливой цены ─→ Фильтры отбора ─→ Сигнал
Tonnel ──┤   и истории сделок    (редкость модели,          (ROI, ликвидность,   ↓
GetGems ─┘   (только цены)        фона, символа)             TTS, тренд флора)  Покупка
                                                                                  ↓
                                                              Лестница переоценки ─→ Продажа
```

Tonnel и GetGems подключены **только как источник цен для сверки**. Если лот
дёшев на MRKT, но так же дёшев везде — это не скидка, а новый уровень рынка.

### Ключевые метрики

| Метрика | Назначение |
|---|---|
| Справедливая цена | `floor × k_model × k_backdrop × k_symbol`, калибровка по фактическим сделкам |
| Балл ликвидности | скорость продаж, время до продажи, глубина книги, поддержка офферами |
| Чистый ROI | `0.95 × наценка − 0.05` — комиссия площадки съедает 5.3% наценки до нуля |
| TTS | прогноз времени до продажи; лот, который не продаётся, — не прибыль |

## Запуск

### Готовый exe

Скачайте `GiftFlipper.exe` из артефактов последней сборки:
**Actions → build → GiftFlipper-windows-x64**. Запустите — браузер откроется сам.

### Из исходников

Нужны Python 3.11+ и Node.js 20+.

```bash
# Фронтенд
cd frontend && npm install && npm run build && cd ..

# Backend
python -m venv .venv
.venv/bin/pip install -r backend/requirements.txt   # Windows: .venv\Scripts\pip
cd backend && python launcher.py
```

Интерфейс откроется на `http://127.0.0.1:8731`. Если порт занят, приложение
само возьмёт соседний.

### Разработка

Фронт с горячей перезагрузкой поднимается отдельно и проксирует API на backend:

```bash
cd backend && FLIPPER_DEV_MODE=1 python launcher.py --no-browser
cd frontend && npm run dev     # http://localhost:5173
```

### Сборка exe

```bash
python build/build_exe.py
```

PyInstaller не умеет кросс-компиляцию — **настоящий `.exe` собирается только
на Windows**. В репозитории это делает GitHub Actions на `windows-latest`,
там же exe запускается и проверяется на живой ответ `/api/v1/health`.

## Безопасность

- Сервер слушает **только `127.0.0.1`** — снаружи подключиться нельзя.
- `paper_mode` включён по умолчанию: сделки симулируются, деньги не тратятся.
- Автомат не включится, пока не выключен paper-режим **и** не заполнен
  whitelist коллекций. Это закрыто тестами в `backend/tests/test_safety.py`.
- Секреты (`api_id`, `api_hash`, сессия Telegram) хранятся в Windows DPAPI
  через `keyring`, а не в файлах рядом с exe. Данные приложения лежат в
  `%APPDATA%/TelegramGiftFlipper` и не попадают в репозиторий.

## Риски — прочитайте до запуска в live

1. **Официального API у площадок нет.** MRKT и Portals — Telegram Mini Apps
   с внутренними эндпоинтами. Они могут измениться без предупреждения.
2. **Автоматизация вне ToS площадок.** Есть риск блокировки аккаунта,
   особенно при userbot-авторизации. Рекомендуется отдельный аккаунт.
3. **Комиссия 5% съедает 5.3% наценки до нуля.** Спред «8%» на деле даёт 2.6%.
4. **Флиппинг не хеджирует рынок.** При падении флоров инвентарь дешевеет
   быстрее, чем набегает прибыль со спредов.
5. **Бумажная прибыль — не прибыль.** Пока лот не продан и комиссия не
   удержана, рост флора ничего не значит.

Прогноз доходности при 100 TON — ориентировочно 1–3 TON в день после выхода
на рабочий режим, при высокой дисперсии по дням. Первый месяц закладывайте
как стоимость калибровки модели, а не как доход.

## Дорожная карта

| Этап | Содержание | Статус |
|---|---|---|
| **0** | Каркас приложения, сборка exe, CI | **готово** |
| 1 | Авторизация через userbot, адаптеры площадок (чтение) | — |
| 2 | Сбор листингов и истории сделок, восстановление TTS | — |
| 3 | Аналитика: редкость, справедливая цена, ликвидность, антифрод | — |
| 4 | Интерфейс: обзор, сигналы, разбор рынка | — |
| 5 | Paper trading и бэктест на собранной истории | — |
| 6 | Реальное исполнение в полуавтоматическом режиме | — |
| 7 | Автомат, риск-лимиты, финальная сборка | — |

## Структура

```
backend/app/
  adapters/    портals, mrkt (торговля) + tonnel, getgems (цены)
  auth/        userbot-сессия и обновление tma-токена
  ingest/      сбор листингов и сделок
  analytics/   редкость, ценообразование, ликвидность, сигналы, антифрод
  trading/     торговый движок, риск-лимиты, исполнение, симуляция
  storage/     SQLite
  api/         REST и WebSocket
frontend/src/  React + Vite + Tailwind
build/         PyInstaller: спека и скрипт сборки
```
